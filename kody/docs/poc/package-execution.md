# Package execution replacement evidence

## Deno default and legacy retirement: 2026-10-05

The local launcher, shared harness, publish bundler and TypeScript checker use
Deno 2.9.7, installed esbuild/TypeScript and the prepared virtual filesystem.
Workerd, worker-bundler, their supervisor, generated compiler/WASM modules and
execution-only dependency tree are removed. OAuth/code utilities and shared
Remix chunks remain generated by `tools/build-platform-modules.ts`. Published
artifact keys and module formats are unchanged; graphs are adapted in memory.
The former workerd selector is rejected, with no automatic fallback.

Trusted npm preparation supports registry semver ranges/tags, captured files and
nested transitive dependencies. Downloads are restricted to the trusted HTTPS
registry, integrity-checked and parsed in memory with installed tar-stream.
Traversal, symlinks, host dependency specifications and install scripts are
denied. Preparation has a 30-second deadline, 300-package/20,000-file limits and
a 64-MiB workspace ceiling. This is not a production npm inventory proof.

Compilation caches include `kody-deno-v1`; Nx test inputs include the backend
selector. Execution carries each surface's deadline and caller cancellation
through the loader and HTTP transport. Preparation checks cancellation before
dispatch; compilation is cancellable. Host shutdown cancels graph reads and
cannot dispatch a graph that resolves afterward. S3 reads have a deadline, abort
signal and size bound. Broker registrations still belong to one process.

The existing soft result/media truncation remains in the calling surface.
Trusted application graphs use 16-MiB evaluation transport headroom and 32-MiB
HTTP body/48-MiB framed-response ceilings; standalone spike defaults remain 100
KiB. Logs, diagnostics and bridge message counts stay bounded. These buffered
POC ceilings are explicit; streaming larger responses and a production package
inventory remain separate work.

Each invocation uses a fresh Deno subprocess and a Worker with no permissions,
an empty inherited environment, a private message port and a private temporary

subprocess bootstrap authenticates stdout frames with a nonce kept out of the
Worker because Deno Workers share stdio. The compiler uses only graph modules
and explicit compatibility modules, with no host-file or registry resolution.
Computed imports use an in-memory graph map; its per-importer expansion is
quadratic and is a documented spike ceiling.

passes on both backends. The HTTP comparison found and fixed Deno's empty

## Step 3 contract and Temporal slice: 2026-10-05

The shared runner contract accepts exactly `{ bundleKey, runToken, runId }`.
Activities, the SDK adapter and HTTP host use the same reference shape, with
surface metadata inside the graph and keys of
`<owner>/runner-inputs/<runId>.json`. The HTTP host authorizes the signed token
against a live broker registration and checks the exact owner/run key before
reading an object. Cross-owner keys, alternate paths, run mismatches, expired
tokens and extra fields do not read graphs, on either backend.

`createRunnerLoader().forContext(context).invokeGraph()` is the shared trusted
preparation path. Direct evaluation/HTTP calls and opt-in target activities
register broker/egress context, store the actual graph, claim dispatch, invoke
and dispose registrations. Evaluation and HTTP response shapes are preserved.
The activity resolver establishes the graph, owner, provenance context and
dispatchers; a mismatched owner is rejected. No signing key or AWS client enters
the Deno Worker. Existing broker/retriever, secret-approval and DNS-pinned
egress protections are reused, not replaced.

Execute retains its workflow-generated run ID. Target package invocations hash
owner, surface and invocation key; target jobs hash owner and Temporal workflow
run/activity identity. Safe pre-dispatch retries retain those IDs and graph
keys. The existing 90-day idempotency store also holds a `runner-dispatch` claim
at the dispatch boundary. Stable-ID loader invocations require this store. An
existing claim or uncertain claim response denies replay; claims are never
released automatically after dispatch. This conservatively sacrifices a run if a
process fails between claiming and sending. Reconciliation is manual, not an
automatic re-execution or backend fallback.

Observed post-dispatch errors become failed activity outcomes; failed outcome
recording is non-retryable. Package-workflow activities mark propagated
post-dispatch runner errors non-retryable. Workflow code, names, queues,
schedules and public inputs are unchanged. A broker restart reports missing
registration before any graph read; registrations remain process-local.

The standalone integration uses the existing `ExecuteRun` and
`PackageInvocation` workflows, a real local Temporal server, signed broker and
egress handlers, the authenticated HTTP host and fresh Deno subprocesses. It
checks duplicate execute after worker restart, safe S3-preparation retry across
worker restart with an unchanged key, lost response after one broker effect,
replay denied after another worker restart, broker restart rejection and zero
remaining registrations. The graph resolver, effect recorder and AWS storage
ports use synthetic local data; this is not the full retained package pipeline
or live S3/AgentCore evidence. The raw spike is still not a standalone
authorized service; only the HTTP wrapper supplies that boundary.

The launcher and shared compatibility harness remain workerd. The Deno HTTP
backend and trusted activity resolver are opt-in test wiring. Step 1/2 corpus,
dependency preparation, cache and surface-budget gates remain open before a
default switch. No cloud resources, deployments or README edits are involved.
